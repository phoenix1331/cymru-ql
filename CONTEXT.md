# CymruQL - Context

Welsh football data (Cymru Premier, Cymru North, Cymru South: 48 clubs) served over both REST and GraphQL from one Laravel app. A React UI loads the same screens from either API and shows what each cost: requests, payload size, timing, DB query count and the raw request or query. Portfolio and learning project. Hobby project with no connection to the FAW, the leagues or any club.

## Runtime

| Item | Value |
|---|---|
| Framework | Laravel 13, PHP 8.4+ |
| Database | MySQL 8, native (WSL, macOS, Linux). Database `cymruql`, created by `php artisan migrate` if missing |
| Tests | Pest 5, in-memory SQLite (`phpunit.xml`), coverage via pcov, 90% minimum on `app/` |
| Front end | Vite (React + TypeScript + Tailwind planned) |
| Containers | None. No Docker, no Makefile |
| Git hooks | Husky (`.husky/`): `commit-msg` (lowercase conventional commits), `pre-commit` (Pint, Larastan, osv-scanner) |
| Static analysis | Larastan, level 6 (`phpstan.neon`) |

## Planned architecture

| Area | Location | Notes |
|---|---|---|
| Seed data | `database/data/*.json` | Shapes in `database/data/README.md`, credits in `database/data/SOURCES.md`. Leagues and seasons hand-maintained; the rest generated by `cymru:import` from the Over the Terraces Cymru config, committed |
| Data objects | `app/Data/` | Readonly DTOs per file plus `DataFiles` (JSON read/write, path from `config/cymru.php` `data_path`) |
| Import | `app/Console/Commands/CymruImport.php`, `app/Import/` | `cymru:import` evaluates the Over the Terraces `cymru.js` module with Node (`OttConfigReader`) and maps rows to clubs and grounds (`ClubImporter`). Source path: `--source` or `OTT_CYMRU_PATH`. `--enrich` fills gaps via `app/Import/Enrichment/` (Wikidata SPARQL, Nominatim reverse geocoding at 1 req/s); `overrides.json` applied last |
| Distance matrix | `database/data/distances.json` | Ground x ground (47 x 47: 48 clubs, one shared ground) road km plus straight-line km, built by `cymru:import --distances` (`app/Import/Distances/`, one OSRM table request). Read via `DataFiles::distances()` (`DistanceMatrixData`). No OSRM calls at runtime |
| Models | `app/Models/` | `League`, `Season`, `Ground`, `Club`, `ClubSeason` (club in a league for a season, final position), `Distance` (directed ground pair, road and straight-line km), `Fixture` (status enum, venue, live minute), `MatchEvent` (type enum, score after the event). Route keys are slugs |
| Seeders | `database/seeders/` | One per JSON file, idempotent `upsert` keyed on slugs; `SlugLookup` resolves slugs to ids and fails on unknown references. `migrate --seed` loads everything in about 2 s |
| Simulation | `app/Simulation/` | `RoundRobin` (double, circle method), `MatchSimulator` (Poisson goals, cards, seeded per fixture), `ClubRatings` (previous season finish), `SeasonGenerator` (weekly Saturday 14:30 UK rounds, results before an as-of moment). Run by `FixtureSeeder` |
| Domain services | `app/Services/` | Shared by REST and GraphQL so the comparison is fair: `SeasonService` (slug or current), `LeagueService`, `ClubService` (paginate, history), `GroundService` (nearby, distances in league), `FixtureService` (`FixtureFilters`), `LeagueTableService` (`TableRow`) |
| Query metrics | `app/Support/QueryMetrics.php`, `app/Http/Middleware/RecordQueryMetrics.php` | `DB::listen` counts queries per request; middleware (on the `api` group, alias `query.metrics`) adds `X-Query-Count`, `X-Query-Time-Ms`, `X-Response-Time-Ms`, `Server-Timing`. Toggle: `CYMRU_METRICS` |
| REST | `routes/api.php` (`/api`, wired in `bootstrap/app.php`, no Sanctum), `app/Http/Controllers/Api/`, `app/Http/Resources/` | Resource oriented: own fields plus slug/name references and `links` to related resources, no deep nesting. Slugs in URLs resolved via services (404 JSON when unknown). Endpoints: seasons, leagues, league table (`meta.basis`: results or final_positions), clubs, club seasons, grounds, nearby grounds, distances in a league (away trips with total), distance between two grounds, fixtures (filters: season, league, club, status, dates, round) and match events. Examples in `request.http` |
| GraphQL | `graphql/schema.graphql` (Lighthouse 6, `/graphql`), `config/lighthouse.php` | Schema first. Simple lookups use `@find`, `@all`, `@paginate` (default 20, max 100) and relation directives (`@belongsTo`, `@hasMany`, batch loaded); derived data goes through the shared services via resolvers in `app/GraphQL/Queries/` (`league`, `table`, `nearbyGrounds`, `Club.league`, `Club.awayTrips`, `Ground.nearby`, `Ground.distancesInLeague`, paginated `fixtures` built from `FixtureService::query`; `Lookup` maps unknown slugs to client-safe `NotFound` errors). Same query-metrics middleware as REST, plus `extensions.metrics` in the body (`app/GraphQL/Listeners/AddQueryMetricsExtension.php` on `BuildExtensionsResponse`). Tests use `MakesGraphQLRequests` |
| Live feed | Lighthouse subscriptions over Reverb | Fixture simulator command pushes match events |

## Decisions

| Decision | Why |
|---|---|
| Native runtime, no Docker | Clone, `composer setup`, `composer dev` on any machine with PHP, Node and MySQL |
| `composer setup` / `composer dev` instead of a Makefile | One familiar entry point that works cross-platform |
| Tests on in-memory SQLite, app on MySQL | Fast, isolated tests with no second database to create; MySQL-specific SQL needs care |
| Committed JSON seed data | Seeding needs no network access; external sources are only hit by `cymru:import` |
| Fixture stores its venue (`ground_id`) | Defaults to the home club's ground but groundshares and neutral venues happen; travel distance is venue based |
| Match events store the score after each event | Live feed and timelines can render any event without replaying the match |
| Results seeded per fixture (`crc32(seed, season, home, away)`) | Same results on every install and every rerun, independent of generation order; only the as-of date decides what has been played |
| REST responses reference rather than embed | Typical REST shape, so a screen needing related data makes several requests; that cost is what the comparison panel shows against one GraphQL query |
| PHP enums registered as GraphQL enums (`PhpEnumType` in `AppServiceProvider`) | One source of truth for `FixtureStatus` and `MatchEventType`; GraphQL values are the PHP case names (`Finished`, `PenaltyGoal`) |
| GraphQL lookups via directives, derived data via services | `@find`/`@paginate` issue the same Eloquent queries the services would; tables, distances and fixture filters reuse the service classes so both APIs compute identically |
| League table computed in PHP from finished fixtures | Two queries, portable across MySQL and SQLite; seasons without fixtures fall back to recorded final positions with null stats |
| Simulated fixtures by default | No API keys needed to run; TheSportsDB is an optional extra |
| Hooks activated by `npm run prepare` | Laravel's `.npmrc` sets `ignore-scripts=true`, so `npm install` skips Husky's `prepare` script; `composer setup` will call it |
| Promotion and relegation via `club_seasons` | League is per club per season; 2025/26 (from Wikipedia) and 2026/27 (from Over the Terraces) are modelled. Past seasons are hand-maintained, the current season is regenerated by `cymru:import` |
| Slugs as join keys in seed data | Club slugs match Over the Terraces for future sharing; ground slugs are name + town because ground names repeat (The Oval, The Recreation Ground) and one ground is shared |
| Node evaluates the Over the Terraces config | The source is a JS module (comments, single quotes); importing it is more reliable than parsing it in PHP, and Node is already required |
| Enrichment fills nulls only, plus an overrides file | Over the Terraces values were reconciled by hand and win; Wikidata has stale entries (old Rhyl F.C. not marked dissolved), so corrections live in a reviewable JSON file |
| Tests block stray HTTP | `Http::preventStrayRequests()` in `tests/Pest.php`; external APIs are always faked |
| Generated placeholder crests | Avoid shipping third-party club badges |

## Commands

**composer**: setup | dev | test | test:coverage | lint | analyse
**npm**: run prepare (activate git hooks)
**artisan**: migrate | db:seed | cymru:import [--enrich] [--distances] | cymru:reset [--as-of=]
**pest**: ./vendor/bin/pest | ./vendor/bin/pest --coverage --min=90
